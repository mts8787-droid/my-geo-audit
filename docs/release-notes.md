# Hiro 릴리즈 노트

Hiro(Dotcom Readability Checker)의 내부 변경 이력. 큰 작업 단위로 묶고 최신이 위. 2026-07 하순부터 상세히 적었고, 그 이전은 맨 아래 "기반 구축"에 요약했다.

**갱신 규칙**
- 채점·감사 결과·화면·확장에 영향이 있는 변경을 커밋할 때, 해당 작업 단위에 한 줄을 추가한다. 새 큰 작업이면 맨 위에 단위를 새로 만든다.
- 단위 = 제목(기간) · 한 줄 요약 · 주요 변경 · 결과/영향(점수는 국가·항목·폭) · 주요 커밋.
- "진행 중 · 미결"은 항상 최신으로 유지한다.
- 버전: 크롬 확장 `extension/manifest.json`(커밋 훅이 자동 증가), API `main.py` FastAPI version.

## 1. #36 인용 가능 문장 — 트러블슈팅·PLP 는 3개 기준 (2026-10-26)

10월 재측정에서 트러블슈팅 SSR 확대로 본문이 보이게 됐는데도 #36 통과율이 20~42% 에 머물렀다. 미달 페이지의 절반 이상이
인용 문장 1~4개 구간이라, 5개 기준이 짧은 콘텐츠에 맞지 않는다는 판단. 사용자 결정으로 트러블슈팅·PLP 는 3개, **10월 감사부터 적용**.

- **사유**: 5개는 PDP·에디토리얼 아티클(익스피어리언스·바잉가이드·뉴스룸)처럼 긴 본문 전제. 트러블슈팅은 증상 → 원인 → 해결책
  세 요소로 끝나고 나머지는 조작 안내, PLP 는 카테고리 설명문 몇 줄이 전부. 3개 = 각 요소 1문장. 3개 기준 통과율(32~61%)이 다른
  타입(56~71%)을 넘지 않아 부풀림은 아니다. `docs/audit-criteria.md` #36 섹션에 사유 서술.
- **룰**: `citable_density_min` 에 `min_count_by_type`("support_troubleshoot:3,plp:3") 추가, 정규식·모델 경로 모두 적용, 모델 조기 중단도
  타입별 임계로. 어드민 파라미터 노출. 항목명 "#36 Citable Sentence ≥ 5개 (트러블슈팅·PLP 3개)". 단위 테스트 1건 추가.
- **대시보드 재채점**: 저장된 모델 확인 개수("모델 확인 N/…")로 타입별 임계에 다시 판정(임계를 낮출 때만 — 측정 당시 임계에서 잘리므로).
  이미 끝난 10월 run(US~MX, 재감사 없이)도 이 경로로 3개 기준이 적용되고, 남은 국가(IN 일부·VN·Global·hs)는 새 코드로 측정.
- 커밋: `1845752`(룰·설정·테스트), `b83bd05`(대시보드 재채점)
