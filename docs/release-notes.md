# Hiro 릴리즈 노트

Hiro(Dotcom Readability Checker)의 내부 변경 이력. 큰 작업 단위로 묶고 최신이 위. 2026-07 하순부터 상세히 적었고, 그 이전은 맨 아래 "기반 구축"에 요약했다.

**갱신 규칙**
- 채점·감사 결과·화면·확장에 영향이 있는 변경을 커밋할 때, 해당 작업 단위에 한 줄을 추가한다. 새 큰 작업이면 맨 위에 단위를 새로 만든다.
- 단위 = 제목(기간) · 한 줄 요약 · 주요 변경 · 결과/영향(점수는 국가·항목·폭) · 주요 커밋.
- "진행 중 · 미결"은 항상 최신으로 유지한다.
- 버전: 크롬 확장 `extension/manifest.json`(커밋 훅이 자동 증가), API `main.py` FastAPI version.

## 진행 중 · 미결

- **v3c 학습 중**(10-21 시작): v3b에서 '기술 작동 설명 = 정의 y'만 빼고 인용 y로만 학습. 끝나면 v2와 같은 정답으로 비교해 배포 여부 결정. `reports/shadow_llm/train/pipeline_v3c.sh`
- **월간 감사 10-25 02:00**: 이 Mac 로컬 + 모델로 실행. 예상 2~4일. 속도가 문제면 `model_scan_max` 축소나 mlx 배치 서버 검토.
- **크롬 웹스토어**: v2.4.2 ZIP 재업로드 필요(`docs/extension-publish-guide.md`).
- **#36 후보 범위**: 사람 라벨 인용문 중 상당수가 정규식 후보에 안 걸림 → #36도 #33처럼 모델이 본문을 훑게 할지 미결.

## 2. 문장 판정 모델 Hiro 도입 — #33 정의문 · #36 인용문 (2026-10-17 ~ 진행 중)

정규식만으로 판정하던 #33·#36을 **자체 학습한 3B 모델이 문장 단위로 확인**하도록 바꿨다. 기준과 조건은 페이블(Claude)로 정의하고, 1차 추출·사람 검수를 거쳐, 올라마 모델을 구성·학습했다. DOM·셀렉터 규칙(#35 등)은 모델이 덮어쓰지 않는다.

**주요 변경**
- 그림자 모드: 점수에 반영하지 않고 정규식과 병행 판정해 사람 판정과 대조(65 + 58문항). 정규식 오탐 보강, doctype·title 본문 혼입 버그 수정.
- 학습 데이터: 페이블로 5,264문장 인용·정의·요약 라벨 → 모델 불일치 186문장 사람 검수(131 수정).
- 모델: Qwen2.5-3B LoRA v1(라벨) → v2(라벨 + 이유) → 올라마 q8_0(q4_K_M은 정의 F1 10p 손실). 템플릿 시스템 프롬프트 중복 버그 수정, `repeat_penalty 1.0`.
- 룰 엔진 결합: 정규식 후보를 모델이 확인, #33은 후보가 없으면 본문 40문장 탐색. `AUDIT_MODEL_URL` 미설정(Render)이면 정규식 폴백이라 Render 점수는 그대로.
- 운영: 모든 감사를 이 Mac 로컬 + 모델로 실행. 올라마 동시 처리 8로 상향(0.68 → 1.1문장/초).
- 트러블슈팅 기준: 검수자가 정의한 유형 코드(D1·D2·C1·C2·C3·N1·N2·I-A~I-I)로 GUIDELINE_TS 수립 → 300페이지 2,931문장 라벨 → 검수 2회(374 + 46문장). 실제 검수가 문서보다 엄격해 보정 섹션 추가(버튼·메뉴 지시 n, 원인은 수치·연식 조건 있을 때만 y).
- 일반 페이지 전면 재라벨 시도 → 사람 검수 대비 인용 재현율 10%로 철회(트러블슈팅 엄격성을 전 페이지로 넓힌 것이 원인).
- 검수자 4개 유형 결정: 각주 n · 상단 핵심기능 단어 나열 n · 수치 없는 기술 작동 설명 y · 용량 안내 y → 해당 유형만 태깅해 `dataset_v3`.
- v3·v3b 평가 → 배포 보류, 운영은 v2 유지.

**결과·영향**

- 사람 검수 문장 기준 인용 F1: v2 67 · v3 59 · v3b 61 / 트러블슈팅 63 · 23 · 62. v3b는 기능 소개문까지 정의문으로 과잉 판정(정의 예측 38 vs 정답 10).
